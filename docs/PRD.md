# Название проекта

> **Historical documentation note.** Historical product requirements. It is not an authoritative runtime specification; use the current code and [canonical docs](README.md).

**Ревьюша**


---

# Для кого продукт

Неопытные разработчики, студенты, фрилансеры, участники open-source проектов и небольшие команды, которым недоступен постоянный Code Review со стороны опытных разработчиков.

Также продукт подходит разработчикам, использующим AI при написании кода и желающим получить независимую проверку качества, архитектуры и потенциальных проблем.

---

# Какие боли решает

* Нет опытного разработчика для Code Review.
* Нет понимания качества собственного кода.
* AI хорошо пишет код, но редко объясняет архитектурные ошибки после генерации.
* Сложно найти потенциальные баги до публикации проекта.
* Новички не понимают, какие ошибки являются критичными, а какие — вопросом стиля.
* Нет единого отчёта по качеству проекта.
* Нет истории изменений качества проекта между версиями.

---

# User Story

> Я как разработчик хочу загрузить свой проект, чтобы получить подробный анализ качества кода, потенциальных ошибок, архитектурных проблем и рекомендации по улучшению без необходимости искать опытного ревьюера.

Дополнительные User Story:

* Я хочу сравнить два анализа проекта и посмотреть, стало ли качество лучше.
* Я хочу задавать вопросы ИИ по конкретным замечаниям.
* Я хочу видеть прогресс анализа в реальном времени.
* Я хочу хранить историю всех проверок своих проектов.
* Я хочу получать MD-отчёт, который можно показать преподавателю, работодателю или заказчику.

# Архитектурные ограничения


Backend — модульный NestJS.

Frontend полностью отделён.

Все длительные операции выполняются только через BullMQ.

API не должен ждать окончания AI анализа.

Все файлы хранятся только в MinIO.

Метаданные — только PostgreSQL.

Кэш — только Redis.

Каждое приложение запускается независимо.

Все сервисы контейнеризированы.

Все API документируются Swagger.

Все изменения базы проходят только через Prisma Migration.

Общий код выносится в packages.

Взаимодействие сервисов только через API или очередь.
