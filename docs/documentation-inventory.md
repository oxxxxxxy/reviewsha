## Supporting and historical material

- `apps/*/README.md` — workspace-specific entrypoints.
- `packages/*/README.md` — package ownership and commands.
- `docs/architecture/00-*` … `14-*` — legacy design notes, marked historical;
  current decisions are in the canonical architecture files and ADR index.
- `docs/implementation/` — execution history and audits. Historical stage
  documents are explicitly marked; `checkpoints`, `completion-audit` and
  `remaining-work` remain active status records.
- `docs/PRD.md` and `docs/plan.md` — original product/implementation source,
  historical and non-authoritative after code implementation.
- `docs/generated/` — generated TypeDoc/OpenAPI artifacts; do not edit manually.

## Refactor rules

1. One canonical document per topic.
2. Historical plans may explain why a decision was made but cannot override code.
3. Generated output is regenerated by scripts, never hand-edited.
4. Every new env, endpoint, queue, migration or deployment value updates the
   matching canonical document.
5. Internal links are validated with `yarn docs:check`.

## Current result

Canonical Getting Started, developer, architecture, backend/frontend, API and
Docker/Kubernetes/Helm guides are available from [docs index](README.md).
Remaining historical documents are retained for traceability and labelled as
such instead of being presented as current instructions.
