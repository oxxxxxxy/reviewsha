# Архитектура монорепозитория проекта "Ревьюша"

## 1. Назначение документа

Этот документ описывает структуру монорепозитория проекта "Ревьюша":

- организацию приложений;
- общие пакеты;
- правила взаимодействия между частями проекта;
- управление зависимостями;
- принципы разработки.

---

# 2. Почему монорепозиторий

Проект использует монорепозиторий на базе Yarn Workspaces.

Причины выбора:

- единое управление зависимостями;
- единая конфигурация TypeScript;
- возможность переиспользовать код между приложениями;
- единый CI/CD pipeline;
- синхронная разработка frontend и backend;
- удобное управление версиями.

# 4. Приложения

## 4.1 Web

Путь:

```
apps/web
```

Назначение:

Основное пользовательское приложение.

Отвечает за:

- регистрацию;
- управление проектами;
- загрузку файлов;
- просмотр анализа;
- просмотр отчётов;
- AI чат.

Технологии:

- React 19;
- Vite;
- TypeScript.

Не имеет доступа к:

- PostgreSQL;
- Redis;
- MinIO;
- внутренним сервисам.

Все данные получает через API.

---

# 4.2 Admin

Путь:

```
apps/admin
```

Назначение:

Административная панель.

Отвечает за:

- управление пользователями;
- просмотр статистики;
- управление системой;
- контроль очередей;
- просмотр логов.

Использует:

- тот же API;
- общие UI компоненты;
- общие типы.

---

# 4.3 API

Путь:

```
apps/api
```

Назначение:

Основной backend.

Отвечает за:

- REST API;
- бизнес-логику;
- авторизацию;
- управление сущностями;
- работу с PostgreSQL;
- создание задач в очередях.

Технологии:

- NestJS;
- Prisma;
- PostgreSQL.

---

# 4.4 Worker

Путь:

```
apps/worker
```

Назначение:

Фоновый обработчик задач.

Отвечает за:

- работу с BullMQ;
- анализ проектов;
- обработку файлов;
- взаимодействие с AI;
- генерацию отчётов.

Worker не принимает пользовательские HTTP запросы.

# 6. Правила зависимостей

## Разрешённые зависимости

```
web
 |
 ├── ui
 ├── types
 ├── sdk
 └── utils


admin
 |
 ├── ui
 ├── types
 ├── sdk
 └── utils


api
 |
 ├── types
 ├── utils
 └── ai


worker
 |
 ├── types
 ├── utils
 └── ai
```

---

## Запрещённые зависимости

Frontend не может:

```
web → database
```

Worker не должен:

```
worker → web
```

API не должен:

```
api → React components
```

---

# 7. Управление зависимостями

Используется Yarn Workspaces.

Основные команды:

Установка зависимостей:

```
yarn install
```

Запуск конкретного приложения:

```
yarn workspace web dev

yarn workspace api start

yarn workspace worker start
```

Добавление зависимости:

```
yarn workspace api add package-name
```

---

# 8. Общие команды проекта

Корневой package.json содержит команды:

```
yarn dev

yarn build

yarn test

yarn lint

yarn typecheck
```

Они запускают соответствующие процессы во всех необходимых пакетах.

Новая функция должна разделяться следующим образом:

Frontend:

```
apps/web
```

Backend:

```
apps/api
```

Фоновые процессы:

```
apps/worker
```

Общие сущности:

```
packages/types
```

Общие компоненты:

```
packages/ui
```

---

# 10. Итог

Монорепозиторий "Ревьюши":

- содержит четыре независимых приложения;
- использует общие пакеты;
- минимизирует дублирование кода;
- позволяет масштабировать части системы отдельно;
- поддерживает единый процесс разработки и CI/CD.

Главный принцип:

> Каждое приложение отвечает за свою область, а общий код существует только в packages.
