# Live AI acceptance test

Обычные unit/integration-тесты не доказывают, что провайдер реально отвечает,
что Worker видит актуальный Prisma Client и что Report сохраняется. Для этого
есть отдельная проверка полного потока:

```text
API → upload → BullMQ/Worker → OmniRoute → DeepSeek Web → report persistence
```

Запускать против уже поднятого deployment:

```bash
LIVE_API_BASE_URL=http://127.0.0.1:13000/api/v1 yarn test:ai:live
```

Скрипт создаёт временного пользователя, проект и файл, запускает настоящий
анализ и завершается с ошибкой, если:

* анализ не достиг `COMPLETED`;
* pipeline не достиг `COMPLETED`;
* хотя бы один review не завершён или завершился ошибкой;
* Report не сохранился и не вернулся через API.

Для существующей сессии можно передать `LIVE_API_TOKEN`. Секреты провайдера
скрипт не принимает и не печатает: они должны быть настроены в deployment.

Для DeepSeek Web через OmniRoute на текущем локальном аккаунте рекомендуются
`AI_MAX_TOKENS=2500`, `AI_INPUT_MAX_TOKENS=2500`, `AI_TIMEOUT_MS=120000` и
`AI_MAX_CONCURRENCY=1`. Таймаут в 6 секунд давал ложные «пустые» ответы до
завершения генерации; это не заменяется mock-тестом.

При включённом `AI_MERGE_FILES=true` Worker сначала передаёт модели только
дерево проекта и просит выбрать до `AI_MAX_ANALYSIS_FILES` файлов, затем делает
один объединённый review выбранных файлов. Исходный код передаётся с номерами
строк вида `12 | code`, чтобы модель могла ссылаться на точную строку.
